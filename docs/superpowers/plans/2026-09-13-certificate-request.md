# Реализация формы справки

1. Добавить `CertificateRequest.astro` и поведение `cert-request.js`, совместимые с действующим публичным API LoyalPro.
2. Подключить компонент для CMS-шаблона `spravka` вместо внешней ссылки.
3. Добавить ограниченный nginx-прокси на публичный домен действующего сервиса.
4. Собрать сайт, проверить nginx, сценарии браузера и мобильную вёрстку без реальных заявок.

## Развёртывание

Сначала установить `deploy/nginx/snippets/peri-cert-request.conf` в `/etc/nginx/snippets/peri-cert-request.conf` и добавить его include в блок сайта, как в `deploy/nginx/stand.conf`. После `nginx -t` перечитать конфигурацию штатным способом. Затем опубликовать сборку сайта. Тот же snippet нужен в server-блоке будущего `peri-clinic.ru`.

Ни Directus-миграция, ни обновление/перезапуск LoyalPro не требуются. Проверка опубликованной версии: GET `/api/public/cert-requests/clinic-1/config` → 200 с `Cache-Control: no-store`, GET `/spravka` → нативная форма; отправку проверять только на согласованной тестовой заявке.

Для локальной разработки/QA нужен nginx со snippet и root на `dist`; один `astro preview` не обслуживает API. Пример проверки: `node scripts/qa/cert-request.mjs http://127.0.0.1:4397`.

Откат: вернуть предыдущую сборку сайта; неиспользуемый публичный прокси можно убрать из server-блока после проверки nginx. Данные в LoyalPro при откате не изменяются.
