# Прайс-лист и коды МКБ-10

## Контекст

На старом Wix-сайте `/uslugi-i-ceny` отрисован кастомным кодом, который на рантайме тянет прайс из git-репозитория и собирает из него PDF-книгу — решение хрупкое и нестабильное (внешняя зависимость в момент показа страницы посетителю). На новом сайте цены сейчас нигде не выводятся.

При этом заготовка уже частично лежит в схеме Directus с исходного дизайн-спека (`docs/superpowers/specs/2026-09-09-peri-site-design.md:73-74`): коллекция **price_items** (`procedure` M2O, `name`, `price`, `unit`, `note`) и флаг `show_prices` в `site_settings`. Ни то, ни другое не подключено к Astro: `price_items` нет в `content.config.ts`, не читается `procedureContent.ts`, не рендерится ни на `/uslugi-i-ceny`, ни на страницах процедур; `show_prices` загружается в `SiteSettings`, но нигде не используется.

Отдельная новая потребность — коды МКБ-10 (показание к процедуре для мед. документации), которых в проекте пока нет вообще.

## Решения

- Прайс остаётся собранным на этапе `astro build` из тех же данных Directus, что и весь остальной контент — никаких рантайм-запросов к внешним источникам на странице. Это устраняет саму причину нестабильности старого решения.
- Модель данных `price_items` не меняется, только подключается к Astro по образцу уже существующих `allFaq`/`allCases` (`src/content.config.ts:390-430`).
- Цены показываются в двух местах: сводным прайсом на `/uslugi-i-ceny` и в собственном блоке на странице каждой процедуры — оба места читают одну и ту же коллекцию `allPriceItems`.
- Код МКБ-10 — новое текстовое поле `icd10` на `procedures` (не на `price_items`): один код на процедуру, показывается публично рядом с заголовком блока цены.

## Модель данных

### `price_items` (без изменений в Directus, только чтение со стороны Astro)

Новая top-level коллекция в `src/content.config.ts`, аналогичная `allFaq`:

```js
const allPriceItems = defineCollection({
  loader: directusLoader('allPriceItems', () =>
    directusGet(
      `/items/price_items${directusQuery({
        fields: 'id,sort,name,price,unit,note,procedure.slug,procedure.title,procedure.category.slug,procedure.category.title',
        filter: JSON.stringify({ procedure: { status: { _eq: 'published' } } }),
        sort: 'sort',
      })}`,
    ),
  ),
  schema: z.object({
    id: z.number(),
    sort: z.number().nullable().optional(),
    name: z.string(),
    price: z.number().nullable(),
    unit: z.string().nullable().optional(),
    note: z.string().nullable().optional(),
    procedure: z.object({
      slug: z.string(),
      title: z.string(),
      category: z.object({ slug: z.string(), title: z.string() }).nullable().optional(),
    }),
  }),
});
```

`price: null` — это и есть «цена по консультации»: редактор оставляет поле `price` пустым и пишет пояснение в `note` (например «Цена определяется на консультации»). Отдельного булева поля для этого случая не заводим — `price === null` уже однозначно означает «нет фиксированной суммы», а текст показать всё равно нужен только в `note`.

### `procedures.icd10` (новое поле в Directus)

```js
f.str('icd10', 'Код МКБ-10', { width: 'half', note: 'например L90.5' })
```

Обычная строка, без строгой regex-валидации формата — это поле для врача, а не для машинной обработки, и в МКБ-10 встречаются уточнения/диапазоны, которые не влезут в жёсткий паттерн `^[A-Z]\d{2}(\.\d+)?$`. Добавляется в `content.config.ts` в схему `procedures` и в выдачу `procedureContent.ts` рядом с остальными полями процедуры.

## Рендеринг

### `src/lib/procedureContent.ts`

Новая функция `getPriceItemsForProcedure(slug)` — та же форма, что `getFaqForProcedure`/`getCasesForProcedure`: `getCollection('allPriceItems')`, фильтр по `procedure.slug`, `bySort()`.

### Страница процедуры (`src/templates/ProcedurePage.astro`)

Новая секция `proc-pricing` между `proc-medical` (показания/противопоказания) и `proc-cases`: таблица «позиция — цена», код МКБ-10 — мелкой строкой рядом с заголовком блока (не в hero, чтобы не грузить первый экран медицинской терминологией).

### `/uslugi-i-ceny`

Под существующей сеткой из 3 карточек-направлений — блок прайса. Разметка — вложенные `<details>` (нативный accordion, без JS, по образцу `Faq.astro`): верхний уровень — 3 направления как обычные секции с заголовком (их всего 3, схлопывать не нужно), внутри каждого — список процедур этого направления как `<details>`, при раскрытии — позиции цен этой процедуры. Источник — тот же `allPriceItems`, сгруппированный на стороне Astro по `procedure.category.slug → procedure.slug`.

### Поведение `show_prices`

Подключаем существующий (сейчас мёртвый) флаг `site.show_prices`. Когда `false`:
- строки позиций остаются видимыми (название процедуры/позиции никуда не пропадает — это ассортимент, важный для SEO и для решения прийти на консультацию);
- вместо суммы — кнопка/ссылка с атрибутом `[data-open-sheet]` и текстом «Узнать цену», открывающая тот же контакт-лист, что и остальные CTA сайта.

Когда `show_prices=true`, но у конкретной позиции `price === null` — вместо суммы выводится текст `note`.

## Не входит в объём

- Экспорт/печать прайса в PDF — не делаем; браузерная печать страницы (`Ctrl+P`) уже даёт читаемый результат за счёт обычной HTML-таблицы, отдельный print-стиль можно добавить позже при необходимости, без усложнения архитектуры сейчас.
- Валидация формата кода МКБ-10 — сознательно не делаем (см. выше).
- Изменение поведения `show_prices` per-процедура — флаг остаётся глобальным (`site_settings`), как и был задуман изначально; per-процедурного оверрайда не вводим, пока не появится реальный кейс.
