Статус: спецификация для реализации; код и CMS в рамках подготовки плана не изменяются.

Референс (десктоп 1440 / мобильная 375, актуальная версия макета):

Макет собран не в графическом генераторе, а реальной Astro-страницей на актуальных данных Directus и токенах `src/styles/tokens.css`/`base.css`, отрендерен и сфотографирован через `scripts/qa/screenshots.mjs` (Playwright + Chrome) на дев-сервере. Это даёт точные шрифты, отступы и реальные фото аппаратов вместо приближения.

## Задача

Заменить плоские карточки каталога `/apparaty` (`src/pages/apparaty.astro`) на карточки в стилистике `CaseCard` (`src/components/results/CaseCard.astro`, страница «Результаты» `/result`): тонкая золотая рамка, скруглённые углы, чип-подпись, серифный заголовок. Десктоп и мобильная версия — в рамках одной страницы (общие стили, адаптив через медиа-запрос, как сейчас).

**Вне рамок**: блок «Технологии» на главной (`src/components/home/Devices.astro`) стилистику карточек не меняет — пользователь решил ограничиться каталогом, чтобы не трогать уже отлаженный слайдер на главной.

## Карточка аппарата (десктоп и мобильная)

Заменяет `.catalog__card` в `src/pages/apparaty.astro`. Разметка и стили по образцу из макета:

```astro
<Tag class="device-card" href={item.href}>
  <div class="device-card__image">
    <span class="device-card__index">{String(i + 1).padStart(2, '0')}</span>
    {item.image ? <Image src={item.image.src} .../> : <span class="device-card__placeholder">{item.name}</span>}
  </div>
  <div class="device-card__body">
    {item.chip && <p class="device-card__chip glass-chip">{item.chip}</p>}
    <h2>{item.name}</h2>
    {item.short && <p class="device-card__desc">{item.short}</p>}
    {item.href && <span class="device-card__arrow" aria-hidden="true">→</span>}
  </div>
</Tag>
```

- Карточка: фон `var(--gold-05)`, рамка `1px solid var(--line-gold)`, `border-radius: var(--radius-lg)`, `overflow: hidden`; при hover — `translateY(-2px)` + `box-shadow: var(--shadow-gold)` (один в один как `.case-card`/`.case-card:hover`).
- Зона фото: фиксированная высота (300px десктоп / `clamp(145px, 42vw, 220px)` мобильная — как в текущей `.catalog__image`), фон `var(--paper)`, снизу разделитель `1px solid var(--line-gold)` — иначе зона фото визуально сливается с телом карточки (тот же тёплый оттенок). Фото — `mix-blend-mode: multiply`, как сейчас.
- Чип производителя/страны — существующая глобальная утилита `.glass-chip` (см. `base.css`, уже используется в `CaseCard`), добавочный класс `device-card__chip` задаёт только цвет/интервалы текста, саму `.glass-chip` в scoped-стиле не переопределять (правило проекта). Если чипа нет (нет ни производителя, ни страны) — просто не рендерится, без пустого места.
- Заголовок — `font: 400 24px var(--display)`, описание — `13px`, `color: var(--muted)`, на мобильной версии — `-webkit-line-clamp: 2` (карточки в 2 колонках, короткие описания не должны раздувать сетку).
- Круглая золотая стрелка-переход — переносится без изменений с текущей `.catalog__arrow`.
- Порядковый номер (`01`, `02`, …) в верхнем левом углу фото — новый элемент, добавляет карточке индексацию, как на `CategoryPage` (`.cat-card__number`) и в мобильной сетке главной (`machine-card > span`).

### Технический нюанс (важно для реализации)

**Не использовать** `display: grid; place-items: center` на контейнере фото вместе с `width: 100%; height: 100%` на `<img>` — в разработке макета это дало реальный баг: при auto-высоте грид-строки процент высоты картинки резолвится как `auto`, и фото рендерится по натуральным пропорциям, вылезая за пределы контейнера и наезжая на подпись под ним (не видно на глаз сразу — оба блока делят один тон фона). Использовать проверенный паттерн, уже работающий в `src/pages/apparaty.astro` и `src/components/home/Devices.astro`: `display: flex; align-items: center; justify-content: center` на контейнере + `max-width: 100%; max-height: 100%; width: auto; height: auto; object-fit: contain` на `<img>` (либо тот же grid-паттерн, но обязательно с `min-height: 0` на img, как в текущем `.catalog__image :global(img)`).

## Сетка

- Десктоп: `grid-template-columns: repeat(auto-fit, minmax(300px, 1fr))` вместо жёсткой `repeat(3, minmax(0,1fr))` — на 1440px даёт 4 колонки при 8 карточках, адаптивно сужается.
- Мобильная (≤800px): без изменений, `repeat(2, minmax(0,1fr))`, gap 12px.
- Заголовок страницы получает золотой акцент через `<em>` (`Аппараты <em>клиники</em>`), под ним — вводный абзац (сейчас на странице только `<h1>` без леда). Текст не хардкодится: в `directus/setup/collections.mjs`, в группе полей «Блок «Технологии»» (рядом с `devices_catalog_title`/`devices_catalog_seo_title`/`devices_catalog_seo_description`), добавляется новое поле `devices_catalog_lead` («Лид каталога»); в `src/lib/homeContent.ts` пробрасывается как `devices.catalog_lead`. Значение по умолчанию при заведении поля: «Оборудование премиум-класса, которое используют врачи PERI CLINIC. Каждый аппарат подобран под конкретную задачу — от лифтинга до лазерной эпиляции.»
- Плашка «Поможем выбрать процедуру» внизу — без изменений по поведению, стили дополняются `border-radius: var(--radius-lg)` для визуальной согласованности с новыми карточками (сейчас `22px`, как у старых).

## Поведение

Без изменений относительно текущей `/apparaty`: карточка с опубликованной связанной процедурой ведёт на её URL; без процедуры — рендерится как `<article>` без стрелки-перехода. Отсутствующее фото — нейтральная область с названием (`device-card__placeholder`), без подстановки чужого изображения. Открытие консультации — существующий `data-open-sheet`, новая форма записи не создаётся.
