# SEO нового сайта PERI CLINIC — 17 сентября 2026

Работы выполнены и опубликованы только для https://prod.peri-clinic.zumrudin.ru. Wix, DNS основного домена и CMS старого сайта не изменялись.

## Результат

- 44 HTML-страницы проверены полностью: 43 доступны для индексации, страница ошибки исключена через noindex и не включена в sitemap.
- Все 43 индексируемые страницы возвращают HTTP 200 и имеют уникальные title и description, один H1 и canonical на собственный адрес prod.
- Проверены 720 фрагментов из production CMS: основные тексты всех 21 процедур, этапы, преимущества, показания, противопоказания, FAQ, документы, биографии, отзывы, результаты и названия позиций прайса. Проверяется присутствие в HTML, а не медицинская достоверность утверждений.
- Проверены 281 URL изображений/видео и вариантов изображений по HTTP: ошибок нет.
- На 43 страницах при двух ширинах (390 и 1440 px) без JavaScript нет скрытых проверяемых текстовых блоков и горизонтального переполнения. Отдельно проверены клиентский переход в каталог, переход на процедуру и открытие записи.
- `npm test`: 17/17. `npm run check`: 0 ошибок, 0 предупреждений (остаются информационные подсказки Astro). Production build, SEO gate и `nginx -t` прошли. У nginx остаются прежние предупреждения об общих настройках HTTP/2 виртуальных хостов; конфигурация валидна.

## Что исправлено

1. Убран HTTP-заголовок `X-Robots-Tag: noindex, nofollow` с нового сайта и его изображений. Админка и dev-стенд сохраняют свои ограничения.
2. `SITE_URL` участвует в сборке. Для нового сайта установлен prod-домен; canonical, Open Graph, JSON-LD, sitemap и robots.txt используют единый адрес. При будущем переносе нужно сменить SITE_URL, пересобрать сайт и настроить постоянные перенаправления со старого домена; это отдельная работа.
3. robots.txt генерируется автоматически. Sitemap содержит 43 уникальных адреса без дубля `/apparaty` и без 404. Ложный lastmod не добавляется.
4. Добавлены постоянные перенаправления с `.html`, `/index.html` и завершающего слеша. Проверено сохранение настоящего статуса 404 для несуществующих страниц. Сохранены старые осмысленные адреса и существующий редирект аппаратной категории.
5. Исправлен конфликт CMS-категории `/apparaty` со статическим каталогом. В каталог добавлены все опубликованные аппаратные процедуры с описаниями, включая ранее недоступные по ссылкам `/microtoki`, `/mikrotokovaya-terapiya`, `/tesla-former`.
6. В 30 записях production CMS обновлены SEO-поля и необходимые тексты. Для 21 процедуры уточнены title с локальным запросом и описания; медицинский смысл исходных описаний сохранён. Исправлены описания специалистов, страницы справки и категорий, метаданные каталога. Уточнены H1 главной, цен, контактов, отзывов и результатов.
7. У двух специалистов удалены явные текстовые заглушки о будущей биографии; вместо них размещены только имеющиеся имя, должность и способ записи. Исправлен устаревший alt портрета. Реальные образование, стаж и достижения не выдумывались.
8. Вместо отсутствующего `/og-default.jpg` используется существующее оптимизированное изображение логотипа; профили специалистов используют портреты. Добавлены Twitter cards, разрешены крупные превью изображений, заполнены alt фотографий каталога.
9. Добавлена связанная разметка WebSite/WebPage/MedicalClinic, Service и Person. Уточнены город, карта, социальные ссылки и формат часов работы клиники. Сохранены FAQ и BreadcrumbList. JSON-LD безопасно сериализуется, CMS HTML очищается в метаданных. Разметка не гарантирует расширенный сниппет; фиктивный рейтинг не добавлялся.
10. Текст видим по умолчанию без JavaScript. Анимация применяется как дополнительное поведение к коротким блокам ниже первого экрана; длинные статьи не ожидают пересечения порога видимости.
11. Все списковые CMS-запросы получают `limit=-1`, чтобы при росте числа материалов не терять страницы и фрагменты из-за стандартного лимита выдачи.
12. SEO-аудит встроен в production build до переключения релиза: ошибки ссылок, метаданных, canonical, sitemap и недоступные из навигации страницы блокируют публикацию.

## Дальнейшая индексация и содержательная работа

Доступность для обхода проверена; фактическое включение всех URL в индекс и позиции не подтверждены. В этой сессии не было авторизованного доступа к Google Search Console и Яндекс Вебмастеру. Для prod нужно подтвердить отдельный ресурс, добавить `/sitemap.xml` и после обхода проверить выбранные поиском canonical, исключённые страницы и поисковые запросы. Прежнее подтверждение основного домена автоматически не подтверждает этот поддомен другого домена.

Для профилей Гаджиевой и Гатауллиной нужны подтверждённые клиникой биографии, сведения об образовании и квалификации. Сейчас страницы содержат корректные, но краткие сведения; SEO не заменяет отсутствующую информацию. Для медицинских материалов желательно назначить фактического ответственного врача и указывать реальную дату содержательной проверки. Авторство и даты не проставлены без подтверждения. Новые отзывы, кейсы и документы должны оставаться подлинными.

Проверка каждого фрагмента на присутствие в HTML не означает, что поисковик обязан отдельно индексировать каждую фотографию, видео или абзац. Это зависит от оценки содержания и качества сайта поисковой системой. Семантику по реальной частотности и спросу следует уточнять по данным Вебмастера/Search Console и Wordstat после накопления статистики; такие данные в сессии не были доступны.
